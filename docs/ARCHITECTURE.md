# Atlas 架构与边界

Atlas 是面向 Linux 的 C++20 模块化单体服务。示例业务是有容量限制的内存键值存储，提供版本条件写入、查询、删除和原子整数累加；另提供可取消的计算任务以展示独立计算线程池。数据只存在于进程内存中，重启后丢失，不提供持久化、复制或事务日志。

## 分层

```text
TCP 客户端
    ↓
Server / Session             连接准入、帧读取、写队列、生命周期、超时
    ↓
protocol                     帧头校验、网络字节序、消息编码
    ↓
Service                      操作路由、参数校验、业务错误转换
    ↓
Repository 接口
    ↓
MemoryRepository             有界内存存储、版本条件更新、原子 ADD

Config / Budget / Metrics / Logger / BoundedPool
为上述模块提供基础设施，不持有业务 Socket。
```

网络层负责可靠传递消息及资源准入，不操作键值存储。业务层处理结构化请求，不访问 Socket。当前规模下路由与业务放在同一模块，但协议帧解析、网络生命周期、存储实现分别独立；没有为每一种操作引入额外的类层次。

## 协议

所有多字节整数使用大端字节序，字符串和二进制值没有终止符。

| 字段 | 字节数 | 含义 |
| --- | ---: | --- |
| Length | 4 | 后续消息体长度，不含自身 |
| Version | 1 | 当前为 1 |
| MessageType | 1 | 请求类型；响应为请求类型按位或 `0x80` |
| RequestID | 8 | 客户端生成的匹配标识 |
| Payload | 可变 | 类型对应的载荷 |

消息体至少 10 字节，最大值由 `max_frame_bytes` 限制。接收端先完整读取固定长度前缀并校验，再读取指定长度消息体，因此不依赖 TCP 数据包边界。一个请求可拆成任意多次发送，多个请求也可合并发送。

响应载荷以 2 字节状态码开始，后面是成功结果或错误说明。状态码：`0` 成功、`1` 参数错误、`2` 键不存在、`3` 版本冲突、`4` 资源不足、`5` 超时、`6` 内部错误、`7` 正在关闭。

| 请求类型 | 载荷 | 成功响应（不含状态码） |
| --- | --- | --- |
| 1 PUT | `u16 key_length + key + u64 expected_version + value` | `u64 version + value` |
| 2 GET | `u16 key_length + key` | `u64 version + value` |
| 3 DELETE | `u16 key_length + key` | 空 |
| 4 ADD | `u16 key_length + key + i64 delta` | `u64 version + decimal_value` |
| 5 HASH | `u32 iterations + seed` | `u64 digest` |
| 6 STATS | 空 | UTF-8 JSON |

键长度为 1–128 字节。PUT 的期望版本为 0 表示无条件写入；非 0 时要求当前版本匹配。ADD 将值作为十进制有符号整数解析，在同一存储临界区内完成读、溢出检查及更新。HASH 的 seed 长度为 1–4096 字节，iterations 范围为 1–10,000,000；它是计算负载演示，不是密码学哈希接口。

同一个连接允许流水线请求，响应可能乱序，客户端必须按 RequestID 匹配，不能依赖响应顺序。尚未完成的 RequestID 不应重复使用。版本和长度错误属于帧错误；未知操作及业务参数错误属于请求错误。客户端请求成功与否不能仅根据 TCP 连接是否保持判断。

## 并发与所有权

一个 `io_context` 由多个 I/O 工作线程驱动。每个 Session 使用独立 strand，Session 状态、读写队列和定时器只通过其执行器访问。strand 保证回调之间不并发执行；协程遇到异步等待时仍可能与其他回调交错，因此协议请求状态仍需显式维护。

每个连接只有一个写循环。写循环持有正在发送帧的 shared_ptr，异步写完成前该帧不会因清空队列而被释放。应用层发送队列和正在写出的数据均计入资源限制。读写协程的完成处理器持有 Session；定时器及计算完成回调只持有 weak_ptr，避免闭环持有。

业务和存储操作交给独立的 `BoundedPool`，计算线程完成后将结果投递到 Session 执行器。线程池的准入上限覆盖正在执行和等待执行的任务；客户端断开或请求超时不代表底层工作已经退出，不会提前释放任务槽位。Job 在真正销毁时才归还全局在途和内存配额，发送帧在异步写结束后才归还内存配额。

共享存储使用有超时的互斥锁保护。读取、版本检查、容量检查和更新按照操作语义在临界区中完成。指标使用原子计数器和固定大小延迟直方图；日志队列有独立锁及消费者线程。业务结果通过任务私有状态转交，避免 I/O 与计算线程共同修改同一个响应对象。

协程的参数和异步操作所需缓冲区必须具有覆盖等待期间的所有权。跨线程任务依赖的服务和基础设施在任务池退出前保持存活。取消是协作式的：取消令牌表达停止意图，不能强制终止任意 C++ 函数。

## 资源限制

| 资源 | 配置项 | 限制目的 |
| --- | --- | --- |
| 活跃连接 | `max_connections` | 限制 Session 和描述符数量 |
| 单帧接收缓冲 | `max_frame_bytes` | 先校验长度再申请内存 |
| 单连接发送 | `max_send_bytes`, `max_send_messages` | 防止慢读客户端耗尽内存 |
| 单连接请求 | `max_inflight_per_session` | 限制流水线深度 |
| 全局在途请求 | `max_inflight_global` | 防止连接数乘以流水线深度失控 |
| 计算任务 | `compute_queue` | 限制等待和执行中的任务总量 |
| 应用受管内存 | `memory_budget_bytes` | 共享预算准入 |
| 存储数据 | `store_bytes`, `store_entries` | 限制数据和容器条目 |
| 日志 | `log_queue` | 满时丢弃并计数，避免 I/O 等待日志输出 |

全局内存预算是应用受管资源的逻辑预算，不等价于进程 RSS 的硬上限。标准库分配器开销、线程栈、Boost 内部对象、内核 Socket 缓冲和页缓存仍需另行考虑。部署时应结合文件描述符限制、系统 TCP 参数和 cgroup 内存上限。当前没有数据库连接池，因为没有真实数据库连接；后续适配器必须增加有界连接池和可取消的下游请求，不能只在 I/O 线程中包一层同步调用。

## 超时与错误语义

`connect_timeout_ms` 用于接受连接后完整收到首次 4 字节长度前缀；TCP SYN 建连过程由 Linux 网络栈管理。后续长度前缀使用 `idle_timeout_ms`；消息体使用 `read_timeout_ms`。这些都是整段读取的绝对期限，不会因收到少量字节而无限延长。`write_timeout_ms` 限制每帧异步写，`business_timeout_ms` 限制请求处理，`downstream_timeout_ms` 限制存储锁等待。

业务截止时间包含任务排队时间。下游等待不能超过业务剩余时间；计算循环周期性检查取消状态。取消及超时后不能继续生成新的业务响应，但已经提交的修改不会自动回滚。客户端收到超时或突然断连时，写入结果可能不确定；需要严格重试语义时，应扩展持久化幂等键机制，RequestID 本身不提供跨连接去重。

单个连接的协议、读写或处理异常转换为该连接的关闭或错误响应。线程入口捕获异常，避免普通连接异常直接逃逸并终止服务。内存彻底耗尽等进程级故障无法依赖同一内存分配器可靠恢复。

## 优雅关闭

SIGINT/SIGTERM 启动关闭：停止接收新连接和新请求，给已接受请求和输出队列留出配置的排空时间，到期取消残余网络操作及计算任务，然后等待取消完成、退出线程并释放基础设施。

关闭的时间保证依赖本项目业务任务遵守取消协议，且下游等待有界。未来接入不能中断的第三方同步驱动时，线程池不能替它提供强制终止能力；应使用驱动原生超时、独立进程隔离或明确降低关闭保证。运维仍可设置 systemd 最终终止期限作为进程级兜底。

## 监控及扩展

STATS 提供结构化运行指标；固定桶直方图给出的 P95/P99 是桶上界估计，不是逐请求排序后的精确百分位。压测工具另外从客户端采样端到端延迟，用来包含排队、传输和协议处理的成本。CPU/RSS 取自 Linux 进程统计，不能解释为整台主机利用率。

服务端延迟直方图为累计的 2 倍幂微秒桶，覆盖准入后的业务排队和执行到响应排队，不包含后续 Socket 发送。`qps` 为最近采样区间收到的请求速率，`lifetime_qps` 为启动以来的平均请求速率；`error_rate` 为累计错误计数/请求计数，错误计数也包含帧错误，因此它不是严格的业务响应失败比例。慢写、业务及读超时共用 `timeouts` 总计。计算队列长度包含运行任务，发送计数包含当前异步写帧。

监控线程采样 procfs 并原子替换可选的最新 JSON 快照文件，文件不累计增长。日志生产者 try_lock 和有界队列使 I/O 线程不等待日志接收端；日志消费者对管道使用非阻塞写，拥堵时丢弃。外部收集器或重定向文件的磁盘轮转由部署环境负责。

扩展 HTTP/1 或 WebSocket 时，可使用 Boost.Beast 作为独立协议适配器，复用业务服务、Repository 和资源准入设施；HTTP 请求体限制、WebSocket 分片上限及写串行化仍需在适配器内落实。接入数据库时替换 Repository 实现，维持 Socket 与业务解耦，补充连接池容量、下游超时、事务和幂等语义。当前不实现 HTTP、WebSocket、TLS、认证、复制或持久化。

默认只绑定 loopback，便于本机和测试环境使用。向网络公开部署前应明确访问控制和加密边界，并按实际负载重新测量资源预算。
